# 집계 도구 두 개 — 무엇을 어디서 보나

`blog.jell.kr` 은 **umami 와 GA4 를 둘 다** 돌린다. 갈아타는 중이 아니라 **의도된 분담**이다
(Jell 결정 2026-09-19). 숫자가 서로 다른 게 정상이므로, 볼 때마다 어느 쪽인지 정하고 본다.

|             | umami                                 | GA4                                          |
| ----------- | ------------------------------------- | -------------------------------------------- |
| 어디        | 자가호스팅 `umami.jell.kr`            | 구글 (`G-XQESSXL8BW`)                        |
| 쿠키        | 안 씀                                 | 씀                                           |
| 무엇에 쓰나 | **트래픽 정본** — 방문·유입원·인기 글 | **수익·검색 다리** — 애드센스, 서치콘솔 연동 |
| 언제 보나   | "이 글이 몇 명한테 닿았나"            | "어느 글이 돈을 버나 / 어떤 검색어로 오나"   |

## 왜 GA4 를 정본으로 안 쓰나

1. **과소집계된다.** 독자가 개발자라 광고차단기 사용률이 높고, GA4 는 차단 목록에 있다.
   자가호스팅 umami 는 상대적으로 덜 막힌다. 절대 수를 믿어야 할 땐 umami 다.
2. **과거가 없다.** GA4 는 2026-09-19 까지 **CSP 에 막혀 수집이 0건**이었다
   (`*.analytics.google.com` 이 베어 도메인 `analytics.google.com` 을 매치하지 않아서).
   그날 풀었으니 이력은 거기서 시작한다.

## 왜 umami 만 쓰지 않나

애드센스·서치콘솔 연동은 GA4 에만 있다. "어느 글이 수익을 내나" 는 umami 로는 원리적으로 못 본다.

## 알아둘 것

- **동의 배너가 없다.** umami 는 쿠키를 안 써서 문제가 없었지만 GA4 는 쓴다. 지금은 한국
  독자 위주라 두고 있고, 해외 유입이 생기면 Consent Mode v2 를 붙일지 다시 정한다.
- **환경변수가 빠지면 GA 는 그냥 안 붙는다**(`config.ts` 폴백이 빈 문자열). 전에는 죽은 UA
  속성으로 폴백해서 **설치된 것처럼 보이는데 아무 데도 안 가는** 상태가 됐다.
- CSP 는 `netlify.toml` 이 정본이고 `public/_headers` 가 같은 값을 들고 있다
  (`src/lib/__tests__/csp-consistency.test.ts` 가 강제). 집계 도메인을 추가할 땐
  **호스트만이 아니라 디렉티브도** 본다 — 같은 도메인이라도 스크립트는 `script-src`,
  비콘은 `connect-src`, 픽셀은 `img-src` 다. 실제로 `adtrafficquality.google` 을
  `connect-src` 에만 넣었다가 `sodar2.js` 가 막힌 채로 남았다.
